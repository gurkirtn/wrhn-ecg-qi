# Contributing

1. Create a focused branch from `main`.
2. Keep patient data synthetic and de-identified.
3. Put interface work in `frontend`, API work in `backend`, and experimental
   model work in `model`.
4. Run the relevant builds and tests before opening a pull request.
5. Describe clinical-safety, privacy, and workflow implications explicitly.

Small changes should remain small. Add a new abstraction only when it has a
clear owner, more than one consumer, or a distinct domain responsibility.
